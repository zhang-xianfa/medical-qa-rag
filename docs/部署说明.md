# 部署说明

## 1. 当前生产环境

| 项 | 值 |
|---|---|
| 服务器 | 腾讯云 CVM，Ubuntu 22.04，2核2G，3Mbps，50G |
| 访问地址 | `http://<服务器公网IP>:8080` |
| 代码目录 | `/opt/medical-qa` |
| 对外端口 | 8080（nginx）→ 容器内 80 |
| 数据库 | pgvector 容器 `medical-db`，不暴露公网 |
| 进程模型 | gunicorn 2 worker（每 worker 一份 torch 模型，2G 内存下不要调高） |

服务器已加 2G swap（`/swapfile`），构建镜像时靠它扛住 pip 安装 torch 的内存峰值。

## 2. 目录与配置文件

```
/opt/medical-qa
├── docker-compose.prod.yml   # 生产编排（db / backend / frontend / nginx）
├── nginx.prod.conf           # 生产 nginx（HTTP 8080，无证书）
├── .env.production           # 生产密钥，权限 600，勿提交 git
├── backend/                  # FastAPI 应用
├── frontend/                 # Vue3 前端
└── docs/                     # 业务文档 + 知识库 JSON
```

`.env.production` 由部署脚本生成，包含数据库密码、JWT_SECRET、ENCRYPTION_KEY、
DeepSeek API Key。**换服务器或重装时一定要先备份这个文件**，丢了会导致所有
登录态失效（JWT_SECRET 变了）。

## 3. 常用命令

```bash
cd /opt/medical-qa

# 查看状态
sudo docker compose -f docker-compose.prod.yml ps

# 看后端日志（排查报错先看这个）
sudo docker compose -f docker-compose.prod.yml logs -f --tail=100 backend

# 重启后端（改代码后）
sudo docker compose -f docker-compose.prod.yml up -d --build backend

# 全量重启
sudo docker compose -f docker-compose.prod.yml restart

# 健康检查
curl http://localhost:8080/api/health
```

## 4. 更新代码

本地改完后两种方式：

**方式 A：整包重传（最省事）**

```powershell
# 本地仓库根目录执行，打包时排除依赖和本地环境文件
tar -czf medical-qa-deploy.tar.gz `
  --exclude=node_modules --exclude=.git --exclude=logs `
  --exclude=__pycache__ --exclude=dist --exclude=.env .
scp medical-qa-deploy.tar.gz ubuntu@<服务器公网IP>:/tmp/
```

```bash
# 服务器上
sudo tar -xzf /tmp/medical-qa-deploy.tar.gz -C /opt/medical-qa
cd /opt/medical-qa && sudo docker compose -f docker-compose.prod.yml up -d --build
```

**方式 B：只重启不重建**：改的是 `.env.production` 里的配置时，`up -d` 即可。

## 5. 知识库更新

知识条目在 `docs/医学参考文献.json`，改完重新入库（会按 content_hash 覆盖同一条）：

```bash
cd /opt/medical-qa
sudo docker compose -f docker-compose.prod.yml exec -T backend \
  python scripts/load_knowledge.py /app/docs/医学参考文献.json
```

入库用的是镜像内置的 `bge-small-zh-v1.5`（512 维），与 `VECTOR_DIM=512` 对应。
**换 embedding 模型必须同时清空 `knowledge_vectors` 表并改 `VECTOR_DIM`**，
否则向量维度对不上会报错。

## 6. 数据库备份 / 恢复

```bash
# 备份
sudo docker compose -f docker-compose.prod.yml exec -T db \
  pg_dump -U postgres medical_qa | gzip > /opt/medical-qa/backup-$(date +%F).sql.gz

# 恢复
gunzip -c backup-2026-10-22.sql.gz | sudo docker compose -f docker-compose.prod.yml \
  exec -T db psql -U postgres -d medical_qa
```

表结构在服务启动时自动创建（`ensure_tables` + `ensure_audit_tables`），
`pgdata` 是 Docker 卷，`docker compose down -v` 会**删库**，别乱用。

## 7. 上 HTTPS / 域名

当前只有 IP + 8080。要加域名和证书：

1. 域名解析到服务器公网 IP（大陆节点需先完成 ICP 备案，否则 80/443 会被拦）。
2. 用 `certbot certonly --standalone -d 你的域名` 申请证书。
3. 把 `nginx.prod.conf` 里 80 的 server 改成 443 + 证书挂载，
   `docker-compose.prod.yml` 的 nginx 端口加 `"443:443"`，挂载 `/etc/letsencrypt`。
4. 同步更新 `.env.production` 的 `CORS_ORIGINS`。

## 8. 常见问题（首次部署踩过的坑，重装时对号入座）

| 现象 | 原因 | 处理 |
|---|---|---|
| 拉镜像 `i/o timeout` | Docker Hub 被墙 | `/etc/docker/daemon.json` 配 `mirror.ccs.tencentyun.com` |
| 构建卡在 `apt-get update` | 容器访问不了 deb.debian.org | Dockerfile 不装 apt 包，健康检查用 Python 标准库 |
| pip 装依赖极慢 | 镜像源对 pip 不友好 | 用清华 `pypi.tuna.tsinghua.edu.cn`（阿里云实测 2m36s vs 清华 14s） |
| torch 下载慢 | download.pytorch.org 国内 ~150KB/s | 用上交大 `mirror.sjtu.edu.cn/pytorch-wheels/cpu`（~16MB/s） |
| RAG 检索为空但接口正常 | `transformers 5.x` 要求 torch≥2.6，低版本会**静默禁用** PyTorch | 锁 `torch==2.9.1+cpu`；入库脚本已加「0 条就退出」保护 |
| `SentenceTransformer load failed: Pooling...` | 模型目录缺 `1_Pooling/config.json`，或 sentence-transformers 版本过新 | 用 robocopy/rsync 完整复制模型；锁 `sentence-transformers==5.3.0` |
| 知识库入库进程被杀（exit 137） | 2 个 worker 已占 ~800M，再加载模型触发 OOM | 先 `stop backend`，再 `run --rm --no-deps` 执行入库 |

## 9. 安全注意事项

- SSH 建议使用密钥登录并关闭密码登录
  （`~/.ssh/authorized_keys` + `PasswordAuthentication no`）。
- `.env.production` 里有 DeepSeek Key 和数据库密码，权限保持 600。
- 数据库没有映射到宿主机端口，只能从容器网络访问，这是有意为之。
- 后端 `/docs` 在生产是公开的，如需关闭可在 `api/main.py` 里设 `docs_url=None`。
